# Fullstack Testing — 详细参考

## 测试能力范围详述

### 1. 功能测试

- 根据业务需求、页面代码、接口文档编写结构化测试用例（正常 / 边界 / 异常）
- 梳理业务流程链路，校验完整业务闭环
- 识别操作逻辑漏洞、按钮状态异常、表单提交异常、CRUD 逻辑错误
- 校验分页、筛选、搜索、排序、导出、批量操作、弹窗交互、提示文案
- 校验新旧数据兼容、字段适配、分页适配器解析稳定性

### 2. 接口专项测试

- DRF 接口：正常入参、空参数、超长参数、非法类型、越权参数、缺失必填项
- 返回格式、错误码、异常捕获、分页结构、入参校验是否符合规范
- 重复提交、并发请求、接口幂等性
- N+1 查询、慢 SQL、数据一致性、事务异常
- 鉴权、Token 过期、权限拦截

### 3. UI/视觉 & 交互体验测试

- 排版、留白、间距、配色、字体、图标统一性
- framer-motion、Sonner、ECharts、空状态/加载/报错兜底
- 多分辨率、浏览器、移动端响应式布局
- 禁用态、Loading、防重复提交、错误/成功提示

### 4. 兼容性测试

- Chrome、Edge、Firefox、Safari 渲染与功能
- PC / 平板 / 手机自适应
- Windows / macOS 展示一致性

### 5. 安全测试基础校验

- 水平/垂直越权
- XSS 注入、参数篡改、敏感信息泄露、未授权访问
- 重复提交、恶意高频请求、参数越界

### 6. 性能测试基础分析

- 前端：重复请求、useEffect 冗余、资源加载、渲染卡顿
- 后端：接口耗时、慢 SQL、无索引查询、批量查询低效
- 简易压测思路与优化建议

### 7. 回归测试 & 迭代测试

- 针对重构、接口改版、兼容清理、配置迁移定制定向回归用例
- 划定回归范围、优先级、验证步骤
- 迭代上线前输出精简准入清单

### 8. 缺陷标准化输出

每条缺陷固定格式见 [缺陷单模板](#缺陷单模板)。

## 单点用例编写流程

### 输入确认

- 目标：页面名 / 接口路径 / 业务模块
- 材料：组件代码、接口实现、需求说明、权限角色（如有）
- 缺失项：主动向用户确认业务规则、状态流转、边界约束

### 页面功能用例表模板

```markdown
# [页面名] 功能测试用例

**测试范围**：[路由 / 组件文件]
**关联接口**：[列出 API]
**测试角色**：[管理员 / 普通用户 / 未登录]

| 用例ID | 模块 | 场景类型 | 前置条件 | 操作步骤 | 预期结果 | 优先级 |
|--------|------|----------|----------|----------|----------|--------|
| TC-001 | 列表 | 正常 | 已登录且有权限 | 1. 进入页面 2. 查看默认列表 | 数据正确展示，分页正常 | P0 |
| TC-002 | 筛选 | 边界 | 列表有数据 | 1. 输入不存在关键词 2. 搜索 | 空状态提示，无报错 | P1 |
| TC-003 | 提交 | 异常 | 表单打开 | 1. 留空必填项 2. 提交 | 字段级校验提示，不发起请求 | P0 |
```

场景类型固定三类：**正常**、**边界**、**异常**。

### 接口专项用例表模板

```markdown
# [接口名] 接口测试用例

**接口**：`METHOD /api/v1/...`
**鉴权**：[Bearer Token / 无 / 角色要求]
**关联 Serializer**：[类名]

| 用例ID | 场景类型 | 请求参数 | 预期 HTTP | 预期响应 | 优先级 |
|--------|----------|----------|-----------|----------|--------|
| API-001 | 正常 | 合法完整入参 | 200/201 | code=0，data 结构正确 | P0 |
| API-002 | 边界 | 分页 page=1, page_size=最大值 | 200 | 分页字段齐全，不超时 | P1 |
| API-003 | 异常-缺参 | 缺少必填字段 X | 400 | 明确错误码与 message | P0 |
| API-004 | 异常-类型 | 数字字段传字符串 | 400 | 校验失败，不 500 | P1 |
| API-005 | 异常-越权 | 用户 A 访问用户 B 资源 ID | 403/404 | 拒绝访问，不泄露数据 | P0 |
| API-006 | 异常-未授权 | 无 Token / 过期 Token | 401 | 统一未授权响应 | P0 |
| API-007 | 并发/幂等 | 相同请求连续提交 2 次 | 200/409 | 不产生重复数据 | P1 |
```

### DRF 接口必测维度清单

- [ ] 正常入参：完整合法请求，响应体 `{ code, message, data }` 符合项目规范
- [ ] 空参数 / 缺必填：返回 400，错误信息可读
- [ ] 超长参数 / 越界数值：校验拦截或安全截断
- [ ] 非法类型：Serializer 校验，不抛未捕获 500
- [ ] 越权：水平（他人资源）、垂直（低权限访问高权限接口）
- [ ] 鉴权：无 Token、过期 Token、错误角色
- [ ] 分页：page、page_size、总数、空页
- [ ] 重复提交 / 幂等：创建、支付、状态变更类接口
- [ ] 并发：库存扣减、唯一约束冲突
- [ ] 敏感字段：write_only 不返回；日志不打印密码/Token

## 回归测试流程

### 适用场景

代码重构、接口改版、兼容清理、配置迁移、业务模块迭代。

### 步骤

```
1. 收集改动说明 → diff、PR 描述、迁移文档
2. 建立「改动点 → 影响面」映射表
3. 划定回归范围 → 直接影响（必测）+ 连带影响（抽样）+ 不动区域（冒烟）
4. 按 P0→P1→P2 编写定向用例
5. 输出回归报告骨架（通过/失败/阻塞项）
```

### 改动点映射表模板

```markdown
# [版本/迭代名] 回归测试方案

## 改动摘要
[1–3 句说明本次改了什么]

## 改动点 → 影响面映射

| 改动点 | 变更类型 | 直接影响模块 | 连带风险 | 回归优先级 |
|--------|----------|--------------|----------|------------|
| 分页适配器统一 | 前端 | 全部列表页 | 旧字段解析失败导致空白 | P0 |
| UserSerializer 字段重命名 | 后端+前端 | 用户详情/编辑 | 编辑提交丢字段 | P0 |
| 删除 v1 响应兼容分支 | 前端 | api/adapters | 个别页面仍走旧解析 | P0 |

## 回归范围

### 必测（P0）
1. …

### 抽样（P1）
1. …

### 冒烟（P2）
1. 登录、首页、核心导航可达
```

### 定向回归用例清单模板

```markdown
| 用例ID | 关联改动点 | 验证目标 | 步骤摘要 | 预期 | 优先级 |
|--------|------------|----------|----------|------|--------|
| RG-001 | 分页适配器 | 列表页分页与空态 | 进入 X 页，翻页，搜无结果 | 数据正确，无 console 报错 | P0 |
```

## 代码走查流程

通读用户提交的前后端代码，主动识别潜在缺陷（非执行测试，偏静态风险发现）。

### 前端走查要点

| 类别 | 检查项 |
|------|--------|
| 请求 | 组件内硬编码 URL；重复请求；useEffect 缺依赖或缺 cleanup |
| 状态 | 提交中未 disable；竞态未取消；列表 key 用 index |
| 适配 | 分页/字段仍走 legacy 分支；adapter 双版本解析遗漏 |
| UI 兜底 | 缺 loading/empty/error；Sonner 未提示失败 |
| 权限 | 仅前端隐藏按钮，未配合接口权限校验 |

### 后端走查要点

| 类别 | 检查项 |
|------|--------|
| 分层 | 业务逻辑写在 Serializer/View 而非 services |
| 查询 | N+1；缺 select_related/prefetch；无索引高频过滤 |
| 事务 | 多表写无 atomic；并发无约束 |
| 安全 | get_object 未校验归属；敏感字段返回；缺 throttle |
| 接口 | 非统一响应体；500 暴露堆栈；分页结构不一致 |

### 走查输出模板

```markdown
# [模块名] 代码走查 — 潜在风险清单

## 摘要
共发现 P0 X 项 | P1 X 项 | P2 X 项

| 风险ID | 等级 | 位置 | 风险描述 | 建议验证用例 |
|--------|------|------|----------|--------------|
| R-001 | P0 | `views.py:42` | 未校验资源归属，存在水平越权 | API-005 越权用例 |
```

## 缺陷单模板

### 单条缺陷（标准格式）

```markdown
【缺陷标题】简短描述现象与模块

- 复现步骤：
  1. …
  2. …
- 预期结果：…
- 实际结果：…
- 严重等级：致命 / 严重 / 一般 / 轻微
- 影响范围：如「所有角色 / 仅管理员 / Chrome 浏览器」
- 修复建议：…
- 证据（可选）：截图路径、接口响应、日志片段
```

### 严重等级判定

| 等级 | 判定标准 |
|------|----------|
| 致命 | 系统崩溃、核心流程完全不可用、数据丢失、严重安全漏洞 |
| 严重 | 主流程受阻、错误数据写入、关键功能不可用 |
| 一般 | 次要功能异常、明显体验问题、可绕过 |
| 轻微 | 文案、对齐、非关键路径 UI 问题 |

### 缺陷汇总表（批量输出）

```markdown
| 缺陷ID | 标题 | 等级 | 模块 | 状态 | 负责人 |
|--------|------|------|------|------|--------|
| BUG-001 | … | 严重 | 用户管理 | 待修复 | — |
```

## 专项测试检查清单

### UI & 交互

- [ ] 排版留白间距符合设计规范；字体图标统一
- [ ] framer-motion 动效正常，无卡顿或无限循环
- [ ] Sonner：成功/失败/警告提示文案正确
- [ ] ECharts：有数据/无数据/resize 场景
- [ ] 空状态、Skeleton、错误页齐全
- [ ] 按钮 disabled/loading；防重复提交
- [ ] 弹窗：打开关闭、ESC、遮罩、焦点陷阱（如适用）
- [ ] 响应式：1920 / 1366 / 768 / 375 无溢出挤压

### 兼容性

- [ ] Chrome、Edge、Firefox、Safari 核心流程
- [ ] Windows / macOS 字体渲染差异可接受
- [ ] 平板竖横屏；手机核心操作可用

### 安全（基础）

- [ ] 水平/垂直越权用例
- [ ] XSS：富文本/备注/搜索框输入 `<script>` 等
- [ ] 敏感信息：接口响应、前端日志、错误页不泄露
- [ ] 未授权接口直接访问返回 401
- [ ] 参数篡改：ID、role、status 等字段

### 性能（基础）

**前端**

- [ ] Network：同一接口是否重复调用
- [ ] useEffect：依赖变更是否引发请求风暴
- [ ] 大列表渲染是否卡顿；是否需虚拟滚动

**后端**

- [ ] 慢接口 >1s 记录路径与 SQL
- [ ] N+1、缺索引、全表扫描风险
- [ ] 批量接口数据量边界

简易压测思路：对核心只读接口用 ab/k6/locust 做阶梯并发，观察 P95 延迟与错误率。

## 示例：缺陷单

【缺陷标题】项目列表分页切换后仍显示第一页数据

- 复现步骤：
  1. 登录管理员账号
  2. 进入项目管理列表（超过 20 条）
  3. 点击第 2 页
- 预期结果：列表展示第 2 页数据，URL 或内部 page 状态为 2
- 实际结果：页码 UI 变为 2，列表仍为第 1 页数据；Network 中 page 参数仍为 1
- 严重等级：严重
- 影响范围：所有带分页的列表页（若共用 Hook）
- 修复建议：检查分页 Hook 中 setPage 与请求参数是否同步；补充 page 依赖
