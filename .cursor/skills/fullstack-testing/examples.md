## 示例 1：单页面功能测试用例

**用户输入**：`@fullstack-testing 为用户管理列表页编写测试用例，角色有管理员和普通用户`

**输出片段**：

```markdown
# 用户管理列表页 功能测试用例

**测试范围**：`/admin/users` · `pages/admin/UsersPage.tsx`
**关联接口**：`GET /api/v1/users/`、`DELETE /api/v1/users/{id}/`
**测试角色**：管理员、普通用户（无权限）、未登录

| 用例ID | 模块 | 场景类型 | 前置条件 | 操作步骤 | 预期结果 | 优先级 |
|--------|------|----------|----------|----------|----------|--------|
| TC-U-001 | 列表 | 正常 | 管理员已登录 | 1. 进入用户管理 2. 查看默认列表 | 用户数据正确展示，分页组件可见 | P0 |
| TC-U-002 | 搜索 | 边界 | 列表有数据 | 1. 输入不存在用户名 2. 点击搜索 | 展示空状态，无报错 Toast | P1 |
| TC-U-003 | 删除 | 异常 | 普通用户已登录 | 1. 尝试访问用户管理页 | 403 或重定向，无删除入口 | P0 |
| TC-U-004 | 删除 | 正常 | 管理员已登录 | 1. 点击删除 2. 确认弹窗 3. 确定 | Sonner 成功提示，列表刷新移除该条 | P0 |
| TC-U-005 | 分页 | 边界 | 总条数恰好等于 page_size | 1. 翻到第 2 页 | 空列表或末页提示，不出现 undefined | P2 |

**待确认项**：删除是否软删除？普通用户是否完全不可见菜单入口？
```

## 示例 2：DRF 接口测试用例

**用户输入**：`@fullstack-testing 为 POST /api/v1/orders/ 编写接口测试用例`

**输出片段**：

```markdown
# 创建订单 接口测试用例

**接口**：`POST /api/v1/orders/`
**鉴权**：Bearer Token（已登录用户）
**关联 Serializer**：`OrderCreateSerializer`

| 用例ID | 场景类型 | 请求参数 | 预期 HTTP | 预期响应 | 优先级 |
|--------|----------|----------|-----------|----------|--------|
| API-O-001 | 正常 | 合法 product_id、quantity | 201 | code=0，返回完整 order 对象 | P0 |
| API-O-002 | 异常-缺参 | 缺少 quantity | 400 | message 指明 quantity 必填 | P0 |
| API-O-003 | 异常-越权 | 用户 A Token + 用户 B 的 cart_id | 403/404 | 不创建订单，不泄露他人数据 | P0 |
| API-O-004 | 异常-未授权 | 无 Authorization | 401 | 统一未授权格式 | P0 |
| API-O-005 | 并发/幂等 | 相同幂等键连续提交 2 次 | 200/409 | 仅产生一笔订单 | P1 |
| API-O-006 | 边界 | quantity=0 或负数 | 400 | 校验失败，不 500 | P1 |
```

## 示例 3：迭代回归测试方案

**用户输入**：`@fullstack-testing 本次迭代删除了分页 adapter 对 items 的兼容，出回归方案`

**输出片段**：

```markdown
# 分页适配器去兼容 回归测试方案

## 改动摘要
移除 `listAdapter` 对旧版 `{items}` 返回体的分支，仅保留 `{data, pagination}` 解析。

## 改动点 → 影响面映射

| 改动点 | 变更类型 | 直接影响模块 | 连带风险 | 回归优先级 |
|--------|----------|--------------|----------|------------|
| listAdapter 删 items 分支 | 前端 | 作品/订单/会员列表 | 分页失效、空白页 | P0 |
| works 服务层解析 | 前端 | 作品管理全流程 | total 计数错误 | P0 |

## 必测（P0）
1. 各列表页首屏加载、翻页、末页
2. 搜索后分页重置为第 1 页
3. 空列表空状态展示

## 抽样（P1）
1. 导出功能是否仍取全量正确
2. 管理后台与用户端列表一致性
```

## 示例 4：标准缺陷单

**用户输入**：`@fullstack-testing 整理缺陷：翻页后列表数据不变，Network 里 page 仍为 1`

**输出**：

```markdown
【缺陷标题】列表翻页后仍展示第一页数据

- 复现步骤：
  1. 管理员登录，进入项目管理列表（数据 > 20 条）
  2. 点击分页器第 2 页
- 预期结果：列表展示第 2 页数据，请求参数 `page=2`
- 实际结果：页码 UI 显示 2，列表仍为第 1 页；Network 请求 `page=1`
- 严重等级：严重
- 影响范围：所有共用 `usePagination` Hook 的列表页
- 修复建议：检查 `setPage` 与 `fetchList` 调用顺序，确保 state 更新后再发起请求；补充 page 依赖
```
