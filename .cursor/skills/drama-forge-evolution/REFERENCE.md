## 3. 进化安全检查清单

在执行任何进化变更前，必须通过：

- [ ] 分析样本 ≥ 3 个完整创作项目
- [ ] 高频缺陷 ≥ 2 次出现（不是偶发）
- [ ] 变更数量 ≤ 3 个条目（本次进化）
- [ ] 不删除任何已有有效规范
- [ ] 变更内容未引入矛盾（与其他角色规范不冲突）
- [ ] 在进化分支上创建，不直接修改主分支
- [ ] PR 描述包含数据证据和预期效果

## 4. 与 Django 后端进化机制的对应关系

| 文件技能进化 | Django 后端进化 |
|------------|----------------|
| 技能 .md 文件 | `SkillRuleConfig` 表记录 |
| EVOLUTION_PROPOSAL.md | `RuleEvolutionProposal` 模型 |
| PR 审批 | `approve_proposal()` |
| git merge | `apply_proposal()` |
| evolution_generation 递增 | `version_tag` 递增 |
| CHANGELOG.md | `note` 字段 + `applied_at` |

两套机制服务不同场景：
- **文件技能进化**：面向 AI 编程工具（Cursor/Codex/Trae），在开发侧改进创作指令
- **Django 后端进化**：面向生产环境运行时，动态更新数据库中的规则配置
