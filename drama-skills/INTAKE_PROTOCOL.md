# 外部内容摄入协议（External Content Intake Protocol）

> 本协议定义如何向 Drama Skills 技能体系提交外部内容，以驱动系统持续进化。

---

## 快速开始

```
1. 将外部内容（文本/链接/描述）提供给 AI
2. 说明来源类型（可选，不说也能自动识别）
3. AI 自动提取并路由
4. 确认归档内容
5. 完成 → 新知识进入系统
```

---

## 提交模板

### 方式一：直接粘贴内容

```
@drama-intake 

[来源类型]: 公众号文章 / 小红书帖子 / PDF节选 / GitHub文件 / 其他
[来源地址]: （可选）https://...
[内容]:

--- 粘贴内容开始 ---
[粘贴完整内容]
--- 粘贴内容结束 ---

[补充说明]: （可选）这是一篇讲XX的文章，我觉得XX部分很有价值
```

### 方式二：提供链接（公开内容）

```
@drama-intake 请分析这个内容并摄入：
链接：[URL]
关注点：[你认为最有价值的部分，可选]
```

### 方式三：描述内容

```
@drama-intake 我看了一部短剧 [剧名]，想把以下规律摄入系统：
[用自己的语言描述你观察到的规律]
```

## 内容来源类型

### GitHub 仓库

**典型场景**：
- 其他 AI 工具的短剧技能仓库
- 编剧工具的提示词库
- 开源的剧本格式工具

**提交示例**：
```
@drama-intake 这是另一个短剧AI工具的仓库，请对比并摄入我们缺失的部分：
[粘贴仓库核心SKILL.md文件内容]
```

---

### PDF 文件

**典型场景**：
- 编剧教材（如麦基《故事》、罗伯特·麦基方法）
- 行业白皮书（短剧市场报告）
- 编剧课程讲义
- 投资方的短剧评估标准

**提交示例**：
```
@drama-intake 这是《X编剧教材》第3章的节选，关于情绪节奏设计：
[粘贴PDF提取文本]
```

**注意**：PDF文本提取后，删除页码、页眉页脚、图表说明等无效内容后再提交。

---

### 公众号文章

**典型场景**：
- 编剧行业分析
- 爆款剧解析
- 平台官方推荐标准解读
- 从业者经验分享

**提交示例**：
```
@drama-intake 公众号文章，[文章标题]，[公众号名称]：
[粘贴全文]
```

---

### 小红书帖子

**典型场景**：
- 高赞短剧创作经验帖
- 受众反馈与追剧心理分析
- 视觉/配乐趋势分析
- 爆款剧的用户讨论

**提交示例**：
```
@drama-intake 小红书帖子，[标题]：
[粘贴帖子+高赞评论]
```

---

### Word 文档

**典型场景**：
- 自己积累的创作经验文档
- 团队内部的创作规范
- 已有剧本的剧本文件
- 复盘总结文档

**提交示例**：
```
@drama-intake Word文档内容，[文档标题]：
[粘贴文档全文]
```

---

### 优秀剧本

**典型场景**：
- 已上线的爆款剧剧本
- 获奖剧本
- 自己的成功作品

**处理方式**：路由至 `@drama-topic-director`，使用六维拉片模块（`modules/tear-down-6d.md`）。

```
@drama-intake 这是剧本《[剧名]》，请进行拉片分析并归档可复用模板：
[粘贴剧本文本]
```

## 摄入后的进化轨道

四轨道唯一定义见 `drama-intake/SKILL.md` 的「四条进化轨道」表，此处仅作流程示意：

```
外部内容 / 创作侧进化信号（评分官提案等）
  ↓
drama-intake 解析
  ↓
┌─────────────────────────────────────────────┐
│  轨道一：规则进化                              │
│  目标：更新 foundation/rules/*.yaml           │
│  触发：方法论补充、阈值修正、LR 新增、          │
│        评分维度连续 2 次 <70                  │
│  流程：提案 → 确认 → 写入 YAML → 记录日志     │
├─────────────────────────────────────────────┤
│  轨道二：灵感归档                              │
│  目标：添加到 inspirations/ 对应库             │
│  触发：具体的钩子/反转/对白/结构案例            │
│  流程：归档确认 → 直接写入                    │
├─────────────────────────────────────────────┤
│  轨道三：市场知识                              │
│  目标：更新 knowledge/market-insights.md      │
│  触发：行业数据、平台趋势、受众分析             │
│  流程：归档确认 → 直接写入                    │
├─────────────────────────────────────────────┤
│  轨道四：新模式发现                            │
│  目标：添加到 inspirations/new-patterns.md    │
│  触发：现有知识库中没有覆盖的全新规律           │
│  流程：提案 → 3+案例验证 → 经轨道一升格为规则   │
└─────────────────────────────────────────────┘
```

## 质量控制

### 接受标准

- **有具体案例支撑**：不接受无案例的纯理论
- **与短剧创作相关**：影视理论需能转化到短剧场景
- **不与现有规则矛盾**：如有矛盾，标记冲突并请用户裁决
- **时效性**：优先2024年及以后的内容（行业变化快）

### 拒绝标准

- 广告/软文（无实质内容）
- 常识性内容（已有大量覆盖）
- 与短剧垂直领域无关的内容
- 只有观点没有实操/案例的内容
