# Tier3 节点流程规则（Node-Specific Flow Rules）

> **来源**：整合 dramaskill `nodes/node-*.md` + ScriptForge `NODE_TIER1_SEED`
> 
> **使用方式**：在对应创作阶段（structure/character/outline/script）执行时，读取本阶段的专属约束。
> **适用角色**：drama-plot-architect / drama-character-designer / drama-script-writer

---

## Node-2：结构与世界观（对应 drama-plot-architect）

### 6阶段集数分配算法

```
按100集为基准，按比例缩放：
阶段1：开篇期 - 10%集数   → 情绪强度 3→6
阶段2：升温期 - 20%集数   → 情绪强度 5→7
阶段3：高潮期 - 20%集数   → 情绪强度 7→9
阶段4：转折期 - 20%集数   → 情绪强度 8→10
阶段5：冲刺期 - 15%集数   → 情绪强度 9→10
阶段6：结局期 - 15%集数   → 情绪强度 10→余韵
```

### 题材节奏调整系数

| 题材 | 开篇期 | 高潮期 | 转折期 | 说明 |
|------|--------|--------|--------|------|
| 家庭复仇 | ×1.2 | ×1.1 | ×1.2 | 压抑期要长，反转要狠 |
| 总裁/甜宠 | ×1.0 | ×1.3 | ×1.0 | 高潮期放大打脸情节 |
| 甜宠/sweet-pet | ×0.8 | ×1.0 | ×1.0 | 快速进入，甜虐交替 |
| 穿越/time-travel | ×1.1 | ×1.2 | ×1.2 | 信息差爽感贯穿 |
| 悬疑/反转 | ×0.8 | ×1.5 | ×1.3 | 中段高密度反转 |

### 世界观必须包含的四个块

```
settingSummary  → 世界背景摘要（50字以内）
rootRules       → 核心规则（≤3条）
coreNouns       → 核心名词定义（题材专有词汇）
dreamIndicators → 梦境三指标预设
```

## Node-3：人设开发（对应 drama-character-designer）

### 角色密度规则

```
主角：1-2人（必须有完整弧光）
核心配角：2-4人（各有独立动机，不可互相替代）
功能型配角：按需（每人必须有1个鲜明识别特征）
总上限：不超过6个需要记住关系的角色

禁止：
  - 创建多个功能相同可以互换的配角
  - 配角没有自己的欲望和动机
  - 反派没有可理解的人性化细节
```

### 人物弧光硬约束

```
每个主角必须有：
  起点状态（第1集）→ 转折点1（约30%处）→ 转折点2（约70%处）→ 终态（结局）

禁止：
  - 主角中途突然改变性格（无触发事件）
  - 反派在结局前突然变好（无铺垫）
  - 主角弧光与全剧主题无关联
```

## Node-4：分集大纲（对应 drama-plot-architect）

### 单集必须包含的六要素

```
1. 本集标题
2. 核心事件（一句话，不超过20字）
3. 情绪强度（1-10）
4. 钩子类型与具体描述
5. 结尾悬念（明确的下集钩子）
6. 出场角色（2-5个）
```

### 大纲质量检验清单

```
全剧检验：
  □ 每5集有一个大反转（≥A级）
  □ 第10-25集（中段）每5集有1个情绪峰值≥8的事件
  □ 阶段4危机情绪值≤2（主角真的到谷底）
  □ 最后3集节奏明显加快

每集检验：
  □ 结尾有明确的下集钩子（不是"故事继续"）
  □ 不连续2集都是纯铺垫（情绪峰值<6）
  □ 出场角色数量合理（2-5人，不超过6人）
```

## Node-5：剧本创作（对应 drama-script-writer）

### 逐集创作硬规则

```
写1集 → gate检测通过 → 再写下1集

禁止：
  - 单次输出≥2集剧本
  - 未通过gate就写下一集
  - 在03_完整剧本/内嵌设定内容
```

### 单集场景约束

```
每集场景数上限：3个场景（竖屏短剧）
每集时长目标：90-120秒（含字幕）
每集台词行数建议：30-50行（对话密集的短剧）

场景内部结构：
  场景头 → 环境建立(1-2行△) → 核心冲突序列 → 情绪收束 → 下场衔接
```

### Gate 检测（每集完成后自动触发）

```
Gate通过条件（全部满足才算通过）：
  □ 场景头格式正确（集号-镜号 时间 内外 地点）
  □ 有明确的情绪高点（≥目标情绪强度）
  □ 结尾有悬念钩子
  □ 无内容漏空（空场景/未完成段落）
  □ 台词无AI腔（直接说情感/信息过载/过于书面）
  □ 字数在合理范围（不过短/不过长）
```

## Node-6：质量审查（对应 drama-script-reviewer + drama-quality-reporter）

### 审查顺序规范

```
1. 格式合规 → 优先级最高，问题多则先修格式
2. 结构检验 → 六阶段+单集四段式
3. 人物逻辑 → 性格一致性+动机合理性
4. 情绪曲线 → 峰谷节点+密度
5. 综合评分 → 八维评分输出JSON
```

---

## Node-7：深度评分（对应 drama-quality-reporter）

### 评分完成后的强制动作

```
1. 输出标准 quality-report.json
2. 将缺陷列表（defects）路由给 drama-script-editor
3. 检查：overall_score < 70 → 触发 drama-evolution-analyst 分析
4. 检查：某维度连续2次 < 70 → 生成技能规则进化提案
```
